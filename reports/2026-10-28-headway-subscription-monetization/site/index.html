Headway Paid Subscription Strategy & Monetization Blueprint

Headway currently runs as a completely free, highly performant Caltrain intelligence engine across iOS, Apple Watch, Android, Wear OS, Even G2 smart glasses, and an MCP server. Transitioning to a paid model requires balancing commuter trust with high perceived value: keep the basic departure board and static timetable 100% free so riders rely on it daily, and paywall continuous autonomous automation (APNs alerts, Live Activities/Dynamic Island, watch complications, and smart glasses heads-up display). Cross-platform access is managed by validating native StoreKit 2 and Google Play Billing receipts through RevenueCat into a single authoritative headway.subscriptions table in Supabase, instantly unlocking paired smart glasses and watches without separate store transactions. The optimal pricing sweet spot for Silicon Valley Peninsula rail commuters is $19.99/year ($1.66/month) with a 14-day free trial, backed by a $2.99/month flexible tier and a $49.99 lifetime option.

Key Trade-Offs & Boundaries

  • Even Hub Inability to Transact: Even Hub does not have an in-app purchase SDK. Glasses must unlock by reading the user's paired device_token linked to the phone's paid account in Supabase.
  • App Store Guideline 3.1.3(b): Cross-platform unlocking is legally permissible as a "Multiplatform Service", provided that StoreKit 2 subscription is also offered natively on iOS.
  • Do Not Over-Restrict Free Boards: If free users cannot see the next train at their nearest station, retention collapses before they can experience real-time alert value.
Executive Recommendation: Launch Headway Pro with a 14-day free trial at $19.99/year (or $2.99/month, $49.99 lifetime) with Family Sharing enabled. Keep basic manual boards free; put push alerts, lock screen Live Activities, watch complications, and Even G2 glasses head-up mode behind Pro. Use RevenueCat with a Supabase webhook to synchronize entitlements across iOS, Android, wearables, and glasses in real time.

What to Keep Behind the Paywall (Free vs. Pro)

A fatal mistake in transit apps is paywalling basic static timetable lookup. When users open an app at the station and find the departure board completely locked, they delete the app and leave a 1-star review. The free tier must establish daily habit and trust.

The guiding rule for Headway is simple: Manual pull is Free; Autonomous push & wearable glanceability is Pro.

1. Free Tier ("Headway Core") — The Habit Builder

  • Live Departure Board: View upcoming departures for the nearest station, complete with real-time delay minutes from 511.org GTFS-RT.

    Background monitoring via Cloudflare Worker cron.ts. Pushes APNs notifications when your specific scheduled train is delayed by >3 min, canceled, or experiencing single-tracking bottlenecks. Alerts you when it is time to leave your desk to catch the express.

    Persistent, real-time trip countdown right on the Lock Screen and Dynamic Island. Automatically updates stops remaining, delay minutes, and platform arrival times without opening the app.

Cross-Platform Paywall Architecture

Headway operates across a diverse fleet of platforms: iOS (SwiftUI), watchOS (SwiftUI), Android (Jetpack Compose), Wear OS (Wear Compose), Even G2 Glasses (.ehpk on QuickJS/Flutter bridge), Cloudflare Worker, and Supabase.

A subscriber must be able to purchase on an iPhone or Android phone and have that entitlement immediately unlock their Apple Watch, Wear OS watch, Even G2 smart glasses, and AI assistant without friction or duplicate billing.

How Each Surface Handles Entitlements

1. iOS & watchOS (Apple App Store)

Implemented using StoreKit 2 (via RevenueCat Swift SDK). Purchases support Family Sharing. Entitlements are saved locally in Keychain and mirrored to Supabase. The companion Apple Watch app receives the entitlement immediately via WatchConnectivity (in WatchSyncState), while also maintaining the ability to verify directly against the Worker API when running standalone on cellular or Wi-Fi.

2. Android & Wear OS (Google Play Billing)

Implemented using Google Play Billing Library 7+ (via RevenueCat Android SDK). When purchased on Android, the entitlement updates the user's Supabase account. The Wear OS companion watch syncs state instantly via the Google Play Services Wearable Data Layer (path /headway/sync_state).

3. Even G2 Smart Glasses (Even Hub .ehpk)

The Even Hub ecosystem currently has no in-app purchase or developer payment API. The glasses plugin runs in an isolated QuickJS container communicating via Bluetooth with the Even app on the user's phone.

Headway already solves this cleanly through its pairing code architecture:
• Free users can pair their glasses and use a 1-day demo / basic departure glance.
• In the Cloudflare Worker api.ts, when the glasses app calls GET /api/board with its device_token, the Worker joins against headway.subscriptions using the token's user_id.
• If the account is Pro, the Worker returns full live HUD telemetry and R1 tracking. If inactive, the glasses display a clean, concise message: "Headway Pro required for smart glasses HUD. Upgrade in the phone app."

4. Web App & Model Context Protocol (MCP)

The Web App and MCP server (at /mcp) authenticate via Supabase Auth session tokens or assistant access tokens (headway.access_tokens). The Worker enforces entitlement checks directly before executing pro tools such as register_smart_alert or create_live_eta_share.

Technical Implementation Blueprint

To implement this model cleanly while adhering to the monorepo's strict graduation and isolation rules (supabase/GRADUATION.md), all billing state is encapsulated within the headway PostgreSQL schema.

Worker Webhook Handler Implementation

The Cloudflare Worker exposes a secured webhook endpoint POST /api/webhooks/revenuecat. When an event fires (e.g. INITIAL_PURCHASE, RENEWAL, CANCELLATION, EXPIRATION), the Worker updates Supabase:

// services/web/src/worker/billing.ts
export async function handleRevenueCatWebhook(env: Env, req: Request): Promise<Response> {
  const authHeader = req.headers.get("Authorization");
  if (authHeader !== `Bearer ${env.REVENUECAT_WEBHOOK_SECRET}`) {
    return new Response("Unauthorized", { status: 401 });
  }

  const payload = await req.json<RevenueCatEvent>();
  const event = payload.event;
  const userId = event.app_user_id;

  const db = admin(env);
  const status = mapRevenueCatStatus(event.type);
  const expiresAt = event.expiration_at_ms ? new Date(event.expiration_at_ms).toISOString() : null;

  await db.from("subscriptions").upsert({
    user_id: userId,
    status: status,
    tier: "pro",
    platform: event.store.toLowerCase(),
    original_transaction_id: event.original_transaction_id,
    product_id: event.product_id,
    expires_at: expiresAt,
    updated_at: new Date().toISOString()
  });

  return new Response(JSON.stringify({ ok: true }), { status: 200 });
}

App Store & Google Play Store Review Compliance

Key Compliance Rules:
  • Apple App Store Guideline 3.1.2 (Subscriptions): The subscription paywall screen must clearly disclose the price, billing duration, payment charged to iTunes account at confirmation, and that auto-renew can be managed in Account Settings.
  • Apple App Store Guideline 5.1.1(v) (Account Deletion): Headway already supports deleting user accounts and revoking tokens. Ensure that deleting an account provides explicit disclosure on how active App Store subscriptions must be canceled via Apple Settings.
  • Family Sharing Support: Configure the IAP product IDs in App Store Connect with Family Sharing enabled. Silicon Valley couples commuting together value this heavily.

Action Plan & Implementation Checklist

  1. Phase 1: Database & Webhook Plumbing — Run the Supabase migration to create headway.subscriptions, add the RevenueCat webhook endpoint in Cloudflare Worker, and wire up service-level entitlement checks.
