    1.3 Full description (max 4,000 characters)

    Paste as-is into the "Full description" field:

    Contempo helps short-term rental hosts log the hours they spend managing their properties — in a form that actually holds up if the IRS ever asks for proof.

    If you're using the STR "material participation" strategy to reclassify rental losses against your W-2 income, the tax code doesn't just require that you did the work — it requires contemporaneous records, logged as the work happens, not reconstructed at tax time from memory. Most hosts who fail an audit don't fail because they didn't do the hours. They fail because they can't prove it.

    How it works:

    • Talk or type what you just did — Contempo turns it into a structured, timestamped entry (property, task, duration, category), asking one quick follow-up only if it can't tell what you meant.

    • Attach a photo as evidence on any entry.

    • Every AI-drafted entry lands as a draft first — nothing is final until you confirm or edit it.

    • Entries logged well after the fact, or described too vaguely, get flagged automatically — visibly, on the entry itself — so you can fix a weak record before it becomes a problem at tax time, not after.

    • A simple dashboard shows hours logged against your threshold, and a CSV export hands your CPA a clean record on request.

    Entry parsing can run entirely on-device (nothing leaves your phone) or fall back to the cloud when needed — you choose which, in Settings.

    Contempo is built by Hejitech for real hosts, starting with one pilot user — this is an early build, and the feature set will keep growing as real usage informs it.

    5. Data Safety Section

    Grounded directly in AndroidManifest.xml's declared permissions, core/model/Entry.kt's actual stored fields, and backend/firestore.rules / storage.rules. One definitional nuance drives most of the "Shared: No" answers below: Google Play's Data safety form defines sharing as transferring data to a third party — sending data to your own backend infrastructure (this app's Firebase/Firestore project, which Hejitech owns and operates) counts as collection, not sharing, since Hejitech remains the first party throughout.

    Top-level questions Does your app collect or share any of the required user data types? Yes, collects — does not share. Is all of the user data collected encrypted in transit? Yes (all traffic is to Firebase over HTTPS/gRPC-over-TLS). Do you provide a way for users to request that their data be deleted? Yes — an in-app "Delete account" flow (Android and web), self-service, immediate. See Section 8.

    8. Compliance Gaps to Close Before Submission

    Gap 1 is now resolved. Gap 2 is real, not paperwork — Play Console will reject or later suspend a listing over it.

    Gap 1 — Resolved: account deletion now works, in-app and on web Both required paths now exist: ui/settings/SettingsScreen.kt has a "Delete account" flow (with a confirmation dialog) alongside "Sign out", and web/src/pages/SettingsPage.tsx has the same flow, reachable without the Android app installed. Both call a shared deleteAccount callable Cloud Function (backend/functions/src/account.ts) that recursively deletes the user's Firestore subtree and Storage files via the Admin SDK, then deletes the Firebase Auth account itself — plus a cleanupDeletedUserData Auth onDelete trigger as a safety net for accounts removed any other way. Verified end-to-end against the emulator suite: seeded data → called the function as the signed-in user → confirmed Firestore docs, Storage files, and the Auth account are all actually gone, for both the direct-callable path and the trigger safety net, and for the full click-through web UI flow (Playwright, sign in → seed → delete → confirm → lands back on sign-in).
    Gap 2 — Privacy Policy page exists, but isn't hosted publicly yet A publicly hosted Privacy Policy URL is a hard requirement of the store listing form (and is separately referenced from the Data safety section). The content itself is done — web/src/pages/LegalPage.tsx renders both the Privacy Policy and Terms of Service from web/src/legal/content.ts, at routes /legal/privacy and /legal/terms, deliberately reachable without signing in (see App.tsx) since Play's review requires that. What's still missing is deploying web/ to a real public URL (e.g. Firebase Hosting — no hosting block exists in backend/firebase.json yet, though the project already has Hosting sites registered: contempo.web.app / contempo-platform.web.app). Once deployed, paste the real URL here:
